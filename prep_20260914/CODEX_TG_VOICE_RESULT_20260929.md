## 구현 결과

- 실제 `media_handler.handle_audio` → 기존 로컬 mlx-whisper large-v3 → `gwdc_tg_adapter.dispatch_message`로 연결했다. 텍스트도 같은 진입점을 사용한다. 관리자 개인 대화와 실제 발신자를 함께 확인하며 원본 chat/message ID·답장·전달 정보를 유지한다.
- 고유 0600 임시파일, 처리 뒤 삭제, 로컬 모델 캐시만 사용, STT 동시 실행 잠금, 빈 전사·명시적 무음 신호 차단을 추가했다. 원음 외부 전송·유료 STT 폴백·새 설치가 없다. 기존 ‘부사장’ 브릿지가 우선하며 일반 음성의 전사 회신은 유지했다.
- ‘두 개’와 ‘2 TRX’, 등록 별칭의 띄어쓰기를 처리한다. 발신 지갑을 수취인 이름에서 추측하지 않는다. 미등록 발신자를 기본 봇 지갑으로 대체하지 않는다.
- 부정·금지·수량 정정·여러 수량·반복 송금·생략된 과거 문맥·잘못된 체인·정밀도 초과를 차단한다. 수량·발신 지갑·수취인 중 필요한 한 항목을 텍스트나 음성으로 다시 받는다. 지원하지 않는 수량을 부분적으로 읽어 축소하지 않는다.
- 요약에 인식 원문을 보존하고, 요약 메시지 ID를 실제 요청 ID에 결합했다. 회신 순서가 뒤집혀도 다른 요청을 승인하지 않는다. 같은 메시지의 중복·동시 처리 및 서로 다른 재전사 결과를 검사했다. 음성·전달 메시지는 승인이 되지 않는다.
- 취소/부정 후 기존 승인 대기를 해제하고 재전달 캐시에도 종료 상태를 반영한다. 상태 파일 오류를 일반 AI 경로로 넘기지 않는다. 실행 후 응답 오류를 ‘송금 없음’으로 단정하지 않는다.

## 서명 코드 인수 보완

수정 전 전무 보고를 그대로 인수하지 않고 코드·모의 재현으로 다음을 확인·수정했다.

1. 실기 정책은 **봇 주소 1개 → 사장 확인 맥북 주소 1개, 정확히 2 TRX, 수수료 상한 2 TRX, 시험 전체 예약 1건**이다. 날짜 변경·예약 해제·재시작으로 새 건수가 생기지 않는다. `--signer local`은 명시된 시험 정책 파일 없이는 기동되지 않는다.
2. 복구 때 승인·주문·원문·정책·만료·중지·원장 결합을 재검증한다. 저장된 raw 거래를 바꿔도 서명 전에 차단한다. SIGNING/SUBMITTING 중단 창은 조사 상태로 남기고 자동 재서명·재방송하지 않는다.
3. 서명 단계·보관 기록은 생성부터 0600, 파일 fsync, 원자 교체, 디렉터리 fsync를 적용했다. 한도 원장은 필수 필드·날짜·금액·상태 전이를 확인하며 파손을 0으로 취급하지 않는다.
4. 키·암호 파일의 최초 생성 권한, 기존 파일 소유자·권한·일반 파일 여부를 검사한다. 실 봇 키는 생성하지 않았다.
5. 재견적 도중 중지되는 경우까지 실제 방송 직전 검사한다. 중지·만료·승인 변경·정책 변경·원장 이상 시 모의 결과는 **서명 1·방송 0·서명본 및 예약 보존**이다.
