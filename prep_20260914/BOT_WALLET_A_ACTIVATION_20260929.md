## 승인 후 진행 순서

1. 키·암호 생성, 주소 확인, 백업·복구 확인. 비밀값은 출력·채팅 전달하지 않는다.
2. 실기 정책의 sender를 검증한 봇 주소에 결합하고 수취인·금액·한 건 상한을 확인한다. `BOT_WALLET_A_TRIAL_POLICY.template.json`은 주소가 비어 있는 준비용 예시이며 그대로 실행할 수 없다. 사장 승인 기록을 붙인 실제 정책 파일만 `--signer-trial-policy`에 지정한다.
3. 사장에게 봇 **공개 주소만** 전달해 Android 자금 공급 한 건을 진행한다. 기존 휴대폰 지갑 키는 이동하지 않는다.
4. 봇 계정 활성·잔액·대역폭·체인 수수료와 실제 unsigned 거래 크기를 조회한다. `quote_trx` 결과로 **2 TRX + 최악 견적 ≤ 봇 잔액**, 견적 ≤ 수수료 상한을 확인한다. 실패하면 공급을 임의로 늘리거나 송금을 실행하지 않는다.
5. 운영 반영 뒤 사장이 Telegram 음성으로 **“봇지갑으로 맥북지갑한테 트론 두 개 보내”**라고 지시한다. 요약의 발신·수취 전체 주소·수량·Nile·수수료·인식 원문을 확인하고 요약에 텍스트 **‘승인’**을 답장한다.
6. 동일 txID 확정·완료 회신·한도 예약→소비·실제 수수료·회신 화면을 기록한다. 모호함·실패·불명 시 자동 재서명·새 거래·재방송은 하지 않는다. 한 건 실행 뒤 접수를 비활성화하고 서버 중지 파일로 차단한다(추가 서비스 재시작 없음).
